## 4. 核心实现（源码级证据）

### 4.1 GameData.dat 段模型与 AMF3 手写读写

`nya_map_core.py:1065-1100` 的 `GameData` 类：`root[section][key] = zlib(AMF3 对象)`。

- 解码：`Amf3Reader(zlib.decompress(raw)).read_value()`（`amf3lite.py:19-158`，支持 u29/整数/双精度/字符串/日期/数组/对象/字节数组，含 string_refs/object_refs/trait_refs 引用表）。
- 编码：`amf3write.py:61-95` 的 `encode_value()` 覆盖 None/布尔/u29 整数/双精度/字符串/字节数组/数组/动态对象；动态对象产出 `0x0a 0x0b 0x01 … 0x01`（无密封成员、空类名）。两文件头均自述"从 `fake_flash_server.Amf3Reader` / `generate_item_dat.encode_value` 原样抽取"，保证与服务端产物一致。

### 4.2 写盘的四重保护（"权威哈希自愈"的技术本体）

1. **先备份**：`GameData.backup("map_<id>")` → `GameData.dat.bak_map_<id>_<时间戳>`（`1103-1107`）。
2. **原子写 + 回读**：写 `.<name>.tmp` → `read_amf(tmp) != root` 则抛错并放弃 → `os.replace`（`1109-1115`）。

### 4.3 手工构造 SWF：DoABC 是"能不能显示"的分水岭

`make_swf_from_parts()`（`727`）产出 `FileAttributes + DefineBitsLossless2/JPEG3 + DoABC + SymbolClass`。关键在 `_doabc_template()`（`476-524`）的注释与实现：

- 客户端 `SwfLibManager.as:106 getBitmapDataFromClassName` 执行 `new classDefined(0,0) as BitmapData`，**要求 SWF 真的定义 BitmapData 子类**；只有 SymbolClass 会 `getDefinition → null` 且被 try/catch 吞掉 → **静默不显示**。
- 工程做法：把一个自带 SWF 的 DoABC 段参数化为 `head(21) + u30(len) + 类名 + sep(0x0d) + tail(140)`；运行期优先从游戏 `swf/{Back,Obj,Map}` 前 80 个文件里**自动定位**模板（`_doabc_template_from()` 527-567 用"`flash.display` 长度字节 + 名字长度自校验"定位），失败才用内置常量 `_DOABC_HEAD_FALLBACK/TAIL`。
- 位图编码二选一：有透明像素走 `DefineBitsLossless2`（`lossless2_body()` 650-681 做 ARGB 预乘 → RGBA 逆变换，`selftest_lossless2()` 682 自测），否则走 `JPEG3`（JPEG + zlib(alpha)）。

### 4.8 生态共同工具底座与"魔改方法论"

**五个共享底座**：

1. **官方权威哈希清单**：`www/act_web_nya_208_isolated/nya211-gamedata-authority.json`（8 个包各一份，2,502~3,860 B）。字段固定：`policy=nya-2.1.1-authoritative-old-fields-only`、`authoritativeJsonSha256=e77578f4…`、`authoritativeAmfSha256=3957118b…`、`legacyFieldSourceSha256=2177687b…`、`topLevelSections=56`、`runtimeGameDataSha256`（每包不同）。实测 v223 / wdnm / 2.2.0 的 `runtimeGameDataSha256` 与 GameData.dat 实际哈希**三者全部零漂移**（`84d8afac…`/`5469c2e8…`/`6e7f7639…`）——"改 GameData 必须同步该哈希"是全生态的硬约束。
2. **FFDec / RABCDAsm 工具链**：反编译到 AS3 → 改逻辑或换素材 → `rabcdasm` 直接改 DoABC p-code → `asc.jar/mxmlc` 重编译。姬水县人版三件齐全（`rabcdasm/` + `tools/_flex_sdk/`），嗯哼版只带 FFDec，Nya 官方线自带 24.1.0/26.2.0。
3. **GameData.dat 的 zlib 流改写**：`zlib.decompress(段) → AMF3 → 改 → AMF3 → zlib.compress`，配"备份 + 原子写 + 回读 + 同步权威哈希"四件套（地图编辑器把这条链做成了产品级）。
4. **AMF3 手工构造**：不引第三方 AMF 库，从 `fake_flash_server.Amf3Reader`/`generate_item_dat.encode_value` 抄成 40~200 行的小模块（`amf3lite.py`/`amf3write.py`/`build_language_packs.read_amf` 同源）。
5. **DoABC 注入**：SWF 里必须有真的 `flash.display.BitmapData` 子类定义，否则"SWF 存在、客户端 200、画面全黑"——这是本生态最贵的一个坑（地图编辑器花了 11 轮反馈才定位）。

**由此形成的"魔改方法论"（四步闭环）**：

`① 反编译取证（FFDec/RABCDAsm 读客户端 AS3、读 GameData） → ② 定点改数据（GameData 段改写 / 编辑器覆盖层 / SWF 素材替换） → ③ 自证（回读校验、逐像素比对、in-game verify、test_dropfix 用例） → ④ 收尾（同步权威哈希 + 刷 version.dat + 重启服务端）`

闭环的判据也很统一：**"改了没反应"归类为缓存/路径问题，"进游戏黑屏"归类为 DoABC/坐标问题，"服务器打不开"归类为权威哈希漂移**——三类症状在该生态的文档里反复出现（`改造说明.md`、`地图背景添加指南.md`、7 份 2.2.3 修复清单）。

### 6.2 安全

1. **签名完整性**：T6 是**唯一校验失败**的对象（`HashMismatch`），且失败原因已定位到真实改动（423down HelpLink）。T5 校验通过（Valid）。
2. **本地无鉴权 HTTP**：地图编辑器与数据编辑器都只在 `127.0.0.1` 监听、无 token；数据编辑器"保存即生效、服务端自动读取覆盖层"，等于**只要能在本机发 HTTP 请求就能改数值**（含 `/api/entities/...` PUT）。这是单机工具的合理取舍，但不应暴露到非回环地址。
3. **任意路径写入**：`GameData.save()`、`deploy()` 会写游戏目录；地图编辑器所有写 GameData 的路径都强制 `sync_authority()`（其注释明说"以前只有 import_map() 会同步，于是点一次小地图服务器就再也起不来"）。
4. **首次运行联网 + 执行远端包**：`启动地图编辑器.bat` 会 `pip install`（清华镜像），无哈希校验、无版本钉死——供应链面应标注。

## 9. 未决问题

1. **T6 的改动范围未穷尽**：只证明了"签名摘要不符"与"注入 423down HelpLink"。要判定是否**仅此一处**改动，需要取得 Adobe 官方同版本安装器原件做逐段比对——本机无原件，**未验证**。
2. **T5 未与 Oracle 官方发布哈希比对**：签名链有效、版本资源一致，但"是否与官方下载字节相同"未验证（需 Oracle 官方 SHA-256 清单）。
3. **T1 作者身份**：与 wdnm V2.6 内嵌编辑器同源（同文件、同工作路径），但**无法证实作者就是 wdnm 分发者**；wdnm、地图编辑器、掉落补丁三者是否同一人也未验证。可见的身份线索只有 QQ 群号 1097398812（T3 内）。
4. **补丁 exe 的 assets/catalog 为何"同尺寸不同内容"**：需把 pyc 反编译（PyInstaller 的 Python 3.8 marshal，需 3.8 解释器）才能定性；本次只到"哈希不同"层级。第 5 个差异模块 `hashlib` 的成因同样**未验证**。
5. **`测试库`/`前端测试库`/`我的地形` 三个自建库的用途**：仅见 `custom.json` 登记与素材，无文档说明；是否为废弃实验未知。
6. **地图编辑器 `export_godot` 的产物去向**：代码存在但包内无 Godot 工程，无法判断是否已实际用于其它项目。
7. **`validate_map.py` 缺失的影响面**：`import_map()` 依赖游戏 `tools/validate_map.py`，但 v223 与 wdnm 的 `tools/` 均无此文件 → 该校验在所有已解包发行版中都会降级为 `[警告] 客户端不变量校验跳过`（本次只做静态确认，未实跑编辑器验证降级文案）。
