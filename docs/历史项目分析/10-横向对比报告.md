## 1. 服务端架构对比

| 维度 | O1/O2 原版 2012 | N1–N4 Nya 官方线 | R2 复刻组 | M1–M6 魔改 |
|---|---|---|---|---|
| 语言 | Java（2 个 fatjar）+ PHP | **Python 3（纯标准库，单文件约 5.7 万行）** | C# net8（游戏服）+ Java 21（GM 后台） | Python 3 |
| 进程数 | 2 个已知（另有缺失的分线战斗服） | 4 个服务线程（1 个进程） | 4（启动器 / 游戏服 / GM 后台 / MySQL） | 同 Nya |
| 端口 | 28522（DB 服）、28523（游戏/分线） | 19280 / 19281 / 19284 / 19285 / 19286 + 843 | 8484 / 8080 / 8088 / 3306 | 同 Nya（wdnm 另开公网广播） |
| 通信协议 | 自定义 F002（MINA）+ BlazeDS/AMF3 | **自研复刻 Flash 二进制协议**：sid/opcode/checksum（`crc_hqx*31+sid`）+ 256 项单向解码盒 `ORIGINAL_CLIENT_DECODE_BOX`（仅上行 `packet[4:-2]` 逐字节逆替换）+ AMF3 | AMF3（mtanksl.ActionMessageFormat）+ 共享数据库轮询 | 同 Nya |
| 依赖 | MySQL、Proxool、Vertrigo 等 | **零第三方依赖**（自带 Python 3.13 embeddable） | 内置 JDK 21、MySQL 8、.NET 8、VC++ | 同 Nya |
| 可独立运行 | ❌ 缺分线战斗服 | ✅ | ✅ | ✅ |

**要点**：O1 只覆盖账号/分线调度/聊天/统计，战斗逻辑服（192.168.100.10:20200-20203）不在包内；Nya 线与复刻组线各自独立实现了完整逻辑服，路线完全不同（前者复刻协议、后者重写服务端并沿用官方客户端 SWF）。

## 2. 数据与存档对比

| 维度 | O1 原版 2012 | Nya 线 | R2 复刻组 |
|---|---|---|---|
| 数据库 | MySQL：`game` **187 张表**（184 MyISAM + 3 MEMORY，849,697 条 INSERT）、`game_proxy` 9 表、`game_statistics` 12 表 | **无数据库**，JSON 存档 | MySQL 8：`game_db` **84 张表**（全 InnoDB，8.0.40 dump） |
| 账号密码 | `game_proxy` MD5 无盐（1,035 账号 / 5,000 激活码） | PBKDF2-SHA256 26 万次迭代 | 游戏服 `accounts` **明文**（test/test123、admin/admin123、player1/123456、Dieu/123456）；GM 面 Argon2id |
| 迁移机制 | 手工导入 SQL | 原子写 JSON（tmp+replace+重试）+ 路径穿越防护 | Flyway V1–V6 迁移（含 baseline legacy-game-schema） |
| 数据资源 | 服务端内嵌数据表 | `GameData.dat`（zlib 流容器，2.68 MB）+ SWF | `GameData.dat.json`（21.7 MB AMF 导出）+ SQL 目录表 |
| 存档隐私 | 无玩家存档 | N2 含他人存档、N3/N4 含测试存档、M5 含 **454 个角色存档文件 / 89,424,476 B** | 包内无玩家存档 |

**要点**：Nya 线用"无数据库 + 文件存档"换来了零安装部署；复刻组线用"现代 MySQL 8 schema + Flyway"换来了可维护性，但游戏侧把口令以明文存库——比 2012 原版的 MD5 还差。

## 11. 关键结论

1. **四条路线互为参照**：O1 是史料与协议源头，Nya 线是"零安装可玩"的最优形态，R2 是"现代工程化重制"的完整样本，魔改生态则是"同一套工具链 + 不同诉求"的六种变体。
2. **版本命名是本库最大的一致性风险**（`2.2.1(九月)` 实为 2.2.0），必须在 [../../VERSIONS.md](../../VERSIONS.md) 与各报告中以 `.nya-version.json` 为准。
3. **隐私问题的分布与"魔改深度"正相关**：越接近真实运营的包（M5、M4、M2）越可能夹带真实玩家数据与明文凭据，收录前必须逐包清洗。
4. **安全能力与工程规范不对等**：R2 的 GM 面（Argon2id/审计/幂等）是全生态最强，但游戏服口令明文；Nya 官方线的协议级权威校验最规范，却在开发快照期完全关闭 GM 鉴权。
5. **AI 辅助开发是全生态共同底色**（官方线、复刻组线、魔改四家皆有硬证据），但人类领域知识（协议逆向、字节码、GBK 编码陷阱）仍是不可替代的部分。
6. **推荐收录顺序**：N1 → N4 → N3 → R2(+R1) → M6 → M3 → O1/O2 → M1 → M5/M4/M2（清洗后）→ N2（仅元数据）。
