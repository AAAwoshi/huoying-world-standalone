## 0. 结论速览

1. `res/` 不是"一个游戏的多个版本"，而是**四条独立技术路线**：2012 原版（Java+PHP+MySQL）、Nya 官方线（纯 Python 复刻）、复刻组线（C#+Java 重制）、以及围绕 Nya 线的**民间魔改生态**（四家、八个可独立运行的端）。
2. **命名陷阱必须记住**：[res/火影世界单机端2.2.1(九月).zip](../../res/火影世界单机端2.2.1(九月).zip) 内部实际是 **Nya 2.2.0**（`nya-local-2.2.0-20260810`，versionCode 10）；真正的官方 **2.2.3**（versionCode 13）在 [res/单机-九月原版/](../../res/单机-九月原版/)。目录名、包名与版本号三者不一致是本库最大的一致性风险。
3. **唯一干净基线**是 [res/火影世界一键端.zip](../../res/火影世界一键端.zip) 内层的 **2.1.1 v8**（声明无存档、无开发痕迹、LF 行尾）。其余包几乎都夹带存档、日志、开发脚本或测试账号。
4. **Nya 线三包不是线性派生**：2.1.1 v8、单机版快照、2.2.0 是同一条开发线在三个时点的三次打包，2.2.0 出自作者 `.codex-temp` 重建目录而非前两个包的内容（证据：备份文件时间戳倒挂、`savePath` 明文路径）。详见本文 **§10.2**。
5. **民间与官方共用同一套工具链**：掉落修复补丁（2026-08-11）的 additive/replacement 掉落模型被官方 2.2.3 原样采用；官方数据编辑器完整源码（2026-08-16）自行公开发布；官方 2.2.3 随包附带修复文档与开发机快照——**民间补丁反向流入官方**是实证。
6. **四条线都由 AI 编码代理深度参与**：Nya 线的 `.codex-temp` 构建路径与 `codexbaseline1` 账号、复刻组线的 `codex_gate_*` 四张验证门禁表与 `www\.claude\` 目录、姬水县人的 42 章交接文档与 427 个 verify 脚本、地图编辑器的 21 轮反馈记录。但人类领域知识（协议逆向、S 盒、GBK 双重编码、Flash 字节码）仍是不可替代的部分。
7. **安全与隐私是收录前的第一道门槛**：原版与复刻组游戏侧明文口令；wdnm 包内明文账密、逐行 token 日志、前端开奖可无限刷元宝；嗯哼 simple 版外发 454 个真实玩家存档（约 92.7 MB）；tzl 关闭 GM 鉴权并跳过 GameData.dat 完整性校验。
8. **收录优先级**：2.1.1 v8（干净基线）> 官方 2.2.3 > 2.2.0 > 复刻组 NarutoWorld（第三条路线的完整实现）> 姬水县人（工程量最大）> tzl / wdnm / 嗯哼（须先清洗隐私并标注安全风险）。

## 2. 四条技术路线

### 2.1 原版 2012（蓝港在线页游服务端）

- **形态**：两个 Eclipse fatjar（`dataServer.jar` 端口 **28522**、`game.jar` 端口 **28523**）+ PHP 门户 + MySQL（Proxool，root/123456）。
- **源码泄漏**：jar 内 `.svn` 目录保留了完整 Java 源码（实测 **19 + 44 份 `.java`**），可还原主类、包结构与配置；协议头为 `0xF0 0x02` + 数位和校验 + `pt/uid/action` 字段。
- **不完整**：`config_lines` 指向 192.168.100.10:20200-20203 的分线战斗逻辑服**不在包内**，这两个 jar 只覆盖账号/分线调度/聊天/统计，**无法独立开服**。
- **前端**：`files.rz.linekong.com\` 是 2012-08-30 官方网页客户端抓包镜像，默认连官方 115.182.54.198:11500，混入 IE 错误页与迅雷插件杂物。
- 详见 [01-原版2012服务端.md](01-原版2012服务端.md)。

### 2.2 Nya 官方线（纯 Python 复刻，当前主线）

- **形态**：单文件 `tools/fake_flash_server.py`（约 **5.7 万行纯标准库 Python**）在字节级复刻 Flash 二进制协议：`sid/opcode/checksum`（校验和 `crc_hqx(payload)*31+sid`）+ **256 项客户端解码盒 `ORIGINAL_CLIENT_DECODE_BOX`（实测为 0..255 的完整置换，定义于 `versions/2.2.1/tools/fake_flash_server.py:392-409`，对应原版 MainLib 的 `CodecUtil.DECODE_BOX`）** + 自研 AMF3；无 Java、无 MySQL，存档为 JSON；自带 Python 3.13 embeddable 运行时，**零安装**。
- **版本谱系**：2.1.1 v8（vc8，2026-08-05）→ 单机版快照（2026-08-07/08）→ 2.2.0（vc10，2026-08-10）→ 2.2.3（vc13，2026-08-12，08-15 前后打包）。
- **端口**：HTTP 19280 / WS-TCP 桥 19281 / 游戏 19284 / 频道 19285 / 原生登录 19286 / Flash 策略 843。绑定地址由环境变量决定：`NARUTO_LOCAL_ONLY=1` 时压回 127.0.0.1（由 `01_启动服务器.bat` 或登录器注入），**默认是 `0.0.0.0` 并公告硬编码的 `27.184.1.224`**——直接运行服务端脚本即公网模式。
- **客户端形态换代**：浏览器 Ruffle → CefFlashBrowser → **NyaMicroClient**（.NET 8 登录器 + Adobe Flash Player ActiveX 34.0.0.251 + Magpie 0.12.1 三套滤镜），云更新机制在 2.2.0 整体退场。
- **2.2.3 的三件大事**：战斗结算重写（不再提前扣血，接入客户端伤害声明）、延迟治理（异步出站队列 + 20Hz 独立 Tick + 存档代际保护）、约 10 组未写入文档的改动（技能射程削顶、第一演习场整波次系统、狂暴野外 Boss 等）。
- 详见 [03-Nya官方线.md](03-Nya官方线.md) 与本文 **§10**。

### 2.3 复刻组线（Java/C# 现代重制）

- **四进程共享一个 MySQL**：C# WinForms 一键端（内置 8080 静态资源服）+ C# net8 游戏逻辑服（8484，AMF3，实测 **105 个 `Handle*`（其中 100 个 async 处理器）/ 189 个 `Build*Packet` / 52 个 `*Request`**）+ Spring Boot 3 GM 后台（8088，**34 条路由**，sa-token + Argon2id + Flyway + 审计）+ MySQL 8（`game_db` 84 表）。
- **零 RPC 协作**：GM 后台直接写玩家表并置 `config_reload.reload_flag=1`，游戏服轮询重载——无 HTTP/MQ 调用。
- **协议还原笔记库**：Flyway V3 预插 `gm_feature_mappings` 七段链路（outer_route/inner_route/server_handler/packet_builder/…），V4–V6 批量导入客户端目录证据（带 source_sha256 证据链）。
- **规模**：6 周从"50 图/50 怪"做到 201 图 / 2903 怪 / 76 NPC / 235 传送点 / 世界 Boss×12。
- **AI 硬证据**：`codex_gate_char_8`、`codex_gate_effects_8`、`codex_gate_equipment_8`、`codex_gate_inventory_8` 四张 Codex 验证门禁表（实测 1 / 0 / 14 / 51 行）+ `www\.claude\` 工作目录。
- **跨线复用**：复刻组线的 `www/.../dat/version.dat` 与 2012 原版**逐字节相同**——官方客户端的资源版本戳被直接沿用。
- 详见 [02-复刻组线.md](02-复刻组线.md)。

## 9. 方法论与勘误（相对旧版文档的修正）

本版相对 2026-10-06/10-07 旧版三篇文档的主要修正：

1. **口径修正**：旧版把"文件数"直接等同包内 `.nya-version.json` 的 `fileCount` 字段。实测该字段与解包文件数不一致（2.1.1 v8：字段 5,604 vs 实测 5,739；2.2.0：字段 5,938 vs 实测 21,161；2.2.3：字段 21,150 vs 实测 21,196）。**源码级定案**：该字段由 `tools/local_package_update.ps1:391` 写入，值是 `$changes.Count`——即"该次云更新实际下载并通过 SHA-256 校验落盘的文件数"，与包内文件总数无关。本版一律以**实测解包树**为准并注明差异；另注 2.2.3 目录里多出的 6 个 `tools/__pycache__/*.cpython-314.pyc` 是 2026-10-07 分析工具运行产生的，不属于原包。
2. **行尾重存切分**：T1→T3 的 37 个"改动"文件中 16 个为纯 LF→CRLF 重存，真实内容改动 21 个——旧版"假人系统缩回 37 KB"等表述已修正为"内容与 2.1.1 完全相同"。
3. **血缘修正**：三包关系由"线性派生"修正为"同一条开发线三个时点打包"，2.2.0 出自 `.codex-temp` 重建目录。
4. **版本号修正**：`2.2.1(九月)` = Nya **2.2.0**；官方 2.2.3 是另一个包。
5. **新增覆盖**：2.2.3 官方修复文档与战斗结算重写、`editor_previews`（15,302 PNG / 618 MB）、`resources/editor_previews` 造成的体积上限、嗯哼三件套演进树、姬水县人 42 章交接文档、地图编辑器与掉落补丁的官方回流。
6. **核验机制**：本版全部关键数字由独立复核（[11-数据核验报告.md](11-数据核验报告.md)）交叉验证；与核验报告冲突时以核验报告为准。

### 10.2 血缘结论：同一条开发线在三个时点的三次打包

T3 **不是**从 T1 或 T2 的包内容派生，而是作者在 `.codex-temp` 重建目录里的重新打包。五条证据：

1. T3 独有 5 个 `MainLib.before-*` 备份，时间戳 **2026-07-25~08-04（早于 T1 发布）**；T2 的 10 个 08-06~08-08 时间戳备份（另加 3 个非时间戳副本）在 T3 中**全部消失**。
2. `MainLib.before-shinra-target-v132.swf` 在 T2 与 T3 中哈希完全相同（T1 没有该备份）。
3. T3 存档 `save/multiplayer/accounts.json` 的 `savePath` 明文记录 `F:\\NarutoSingleplayer\\.codex-temp\\nya211-rebuild-20260810-v1\\…-20260808-v9-final\\…`。
4. 全树 16 个文件统一 LF→CRLF 重存，是换机器/换打包流程重新落盘的特征。
5. T1 的 MainLib ≈ T3 独有的 v245 备份 + 影分身渲染 4 类改动（反编译比对），说明 T1 出自同一条开发线的更早期。
