### 2.2 协议（客户端实测）

- 帧：`int32BE len \| u16BE sid \| u16LE opcode \| body \| u16BE checksum`（`BaseClient.as:225-234`）
- 服务端先剥离 4B 前缀再解析（`fake_flash_server.py:11504-11511`）→ **wire 与 deframed 是两个视图**
- `body` 经 `CodecUtil` **256 项 S-box** 代换；`checksum = CheckSumUtil*31 + sid`
- 服务端：ClientOpcode **122** / ServerOpcode **164** / 处理器 125 条覆盖 121；`VERSION=79`；`HELLO(mac)`；`PING(20)`→`PONG(19)`

### 2.4 数据格式（源码级结论）

**先明确 SWF 是什么**（本项目最重要的输入格式）：**SWF = Flash 的"可执行资源包"**——一个文件里同时装着矢量/位图美术、帧动画、音频、字体，以及 **ActionScript 字节码**（即可运行的程序），由 Flash Player 的 AVM1/AVM2 虚拟机执行。结构上是「头 + 标签流」：

- **头**：签名 `CWS`（zlib 压缩）/ `FWS`（不压缩）/ `ZWS`（LZMA）+ 版本 + 文件长度 + 舞台矩形 + **帧率** + 帧数；
- **标签流**：`DefineBitsJPEG3`、`DefineBitsLossless2`（位图）、`DefineShape`（矢量）、`DefineSprite`（帧序列动画）、`DoABC`（AVM2 字节码）等。

**本项目实测口径**（客户端目录 5,425 个 SWF，解析失败 0）：

| 指标 | 值 |
|---|---|
| 签名分布 | `CWS` 5,394 / `FWS` 31 / `ZWS` 0；SWF 版本 9 → 5,202、10 → 196、17 → 9、43 → 18 |
| 内嵌位图 tag | **25,307 个 / 293.9 MiB**（`JPEG3` 20,320 / 271.8 MB；`Lossless2` 4,615 / 35.7 MB） |
| 帧序列 | `DefineSprite` **5,889** 个 |
| 矢量形状 | `DefineShape` **3,998** 个 |
| 游戏代码 | `DoABC` **5,488 个 / 53,604,823 B**（≈51 MB 字节码，即 4 个主 SWF 里的游戏逻辑） |
| 资源 SWF 分布 | `swf/` 32 个子目录 / 5,412 文件：`Char` 145（93.1 MB）、`Mob` 324（63.1 MB）、`Skill` 432（53.8 MB）、`Obj` 663（28.6 MB）… |
| 骨骼数据 | **无** → 动画是"位图帧序列 + 矢量形状" |
| 原版帧率 | **36 fps**（来自 SWF 头，`MainLoader.as:44`） |

**为什么它是重写的核心障碍**：① 格式已死（Flash 2020-12 停更、2021-01 激活 kill switch），任何现代引擎都不认 SWF；② 资源按**类名**寻址（`ApplicationDomain.getDefinition`，`ResourceManager.as:424`）——这就是"美术按类名打包进 5,425 个 SWF"的含义；③ 连 FlasCC 模块也是 SWF 里的 AVM2 字节码，非 Flash 目标无法运行。
→ 因此方案定为**离线转码**：SWF → 图集 + 帧表 + 类名索引 + 内容包，**运行时零 AVM2 依赖**（详见 §3 资产行与《重写方案》§3.6）。

- `GameData.dat` = **AMF3 + zlib 嵌套容器**（2,678,097 B；56 顶层段 / 5,197 节点 / 5,135 个 zlib 段；膨胀 2.44x；尾随 0）——可 100% 解析
- **U29S 字符串不带 null 终止符**（非规范）→ **严格按 AMF3 规范的第三方库会读取失败**，必须自持读取器
- `DatCrypto` = AES-128-CTR + 混淆 + 双校验（魔数 `XGD2`）；`ResCrypto` = AES-128-CTR（`XXG1`）；**但资产实际未加密**（`ResCrypto.setKeyHex` 全树 0 调用点，`ResourceManager.as:192-198` 空 catch 返回原文）
- SWF 内嵌位图 **25,307 tag / 293.93 MiB**（JPEG3 20,320 / Lossless2 4,615）、DefineSprite 5,889、**无骨骼数据**
- 官方"数据编辑器完整源码"是 **Python 3.8 + 原生 Web**，不是 Java

### 2.5 工具链：FFDec 的角色与风险（构建期依赖，不进运行时）

**FFDec（JPEXS Free Flash Decompiler）是什么**：开源的 SWF 反编译/编辑工具（Java 实现）。四个能力：
① 反编译 AS1/AS2/AS3（AVM1/AVM2 字节码）→ ActionScript 源码；
② 导出 SWF 内资源：位图（JPEG3/Lossless2）、矢量形状、Sprite/帧序列、字体、声音；
③ 编辑并**回写** SWF（换素材、改脚本）——仓库里的"变身卡替换工具"就是此用途；
④ 命令行批处理（`-export script|image|sprite|frame|sound …`）。

**在本项目里的四个角色**：

| 角色 | 状态 | 证据 |
|---|---|---|
| 反编译 AS3 → 重写依据与统计基线 | ✅ 已完成 | `spikes/src-evidence/client/decompiled/**`：Main 320 / MainLib 1,897 / MainLoginServer 325 / MainCreateChar 57 = **2,599 个 .as**（工具树 `spikes/src-evidence/client/tools/ffdec_25.1.3/`，79 文件） |
| 资产抽取：SWF → 位图/帧序列 | 计划中（M0-④ 覆盖率、M3 管线） | 待抽取对象：**25,307 个位图 tag / 293.93 MiB**、DefineSprite 5,889 |
| 保真基线：导出原版动画帧供逐帧对比 | 计划中 | 与 §5 的保真专项配套 |
| 模组工具：替换素材（变身卡等） | 社区既有用法 | `res/变身卡替换工具/ffdec_25.1.3.zip`（19,522,527 B）+ 随包 `jdk-8u321` |

**试点实跑（2026-10-08，脚本与产物见 `spikes/swf-pipeline/`）**：

| 项 | 值 |
|---|---|
| 样本 | `swf/Mob/Mob_1000006.swf`（46,757 B，CWS，SWF v9，舞台 550×400，**40 fps**，时间轴 1 帧） |
| 标签 | **18× `DefineBitsJPEG3`** + `SymbolClass` + `DoABC2` + `ShowFrame` … |
| 产物 | 18 帧 PNG → **图集 1024×256 RGBA8（123,689 B）** + `atlas.json`（帧表 + **源 SWF sha256 溯源**） |
| 还原动作 | **stand(4) / move(4) / attack1(4) / hit1(1) / die1(5)** |
| 关键发现 | 导出文件名即 **符号类名** `{资产}_{动作}_{帧号}` → **动画表可直接从类名重建**，无需反推时间轴（与 `ApplicationDomain.getDefinition` 的按名寻址一致） |
| 依赖 | FFDec（构建期 Java）+ **纯标准库 Python 打包器**；产物仅为 PNG+JSON，**运行时零 AVM2 依赖** |
| 下一步 | M0-④：对 `swf/` 全量 5,412 个批量跑，产出覆盖率报告与失败回退策略；矢量型/嵌套 Sprite/锚点/滤镜未验证 |

**为什么必须锁定具体版本（25.1.3）**：
1. 它是仓库内**随包分发**、且本次分析实际使用的版本 → 结果可复现；
2. **反编译输出依赖版本与流程**：实测两份反编译产物在 **237 / 1,897 个文件（12.5%）**上不一致，现场重导证明其中一份**丢了真实语句** → 必须"锁版本 + 锁参数 + 产物入库"；
3. 生态里存在**其他版本**：Nya 官方 `build_language_packs.py:50` 指向 **ffdec_26.2.1** → 跨版本混用会产生不可比的结果。

**已知限制（必须在方案里承认）**：
- Java 工具 → **构建期**依赖 JDK（不随运行时分发）；
- **FlasCC/Alchemy 编译的 AVM2 字节码**（本项目 `cmodule/**` 183 类 / 65,934 行）只能得到 `avm2.intrinsics` 级伪码，**无法还原 C 源码** → 这是前置 spike ③ 的核心难点；
- 反编译产物缺少类型与注释，嵌套 MC/时间轴脚本可能不完全等价，直译需人工判断；
- 许可：第三方工具，若随包分发需核对许可条款（**未核实**）。

| 层 | 选型 | 理由（要点） |
|---|---|---|
| 总架构 | 单进程 + 程序集依赖规则 + 可切外置 Bot Host | 多进程**不提高仿真上限**（确定性要求单线程改世界），却**恶化内存/显存**（每进程一份资产）；用编译期依赖规则替代进程边界，成本≈0 且随时可拆 |
| 语言 | C#/.NET 全栈 | 契约/规则/预测/机器人共享同一程序集；一个工具链；性能对本场景过剩 |
| 客户端引擎 | Godot 4.7.x（.NET） | MIT（无厂商锁定）；2D 优先；Control UI + AnimationPlayer + TileMap 内置；headless 导出可进 CI；**多窗口已实测** |
| 核心逻辑 | 无头类库，纯函数 | 可 headless 测试、可被机器人/对拍驱动；`Rules` 不含 I/O 与时钟 |
| 协议/契约 | 语义冻结 + 编码重写 + 兼容网关（可选） | 语义是规格（重写=重新发明 40 个玩法域）；编码重写换来版本化/批量/增量（直接解决混战 fan-out）；旧编码网关让原版客户端可直连验证（详见《重写方案》§3.7） |
| 服务端 | 单线程确定性 tick 20 Hz + 边界线程池 | 确定性 = 可回放、可对拍、可定位分歧 tick；I/O 不阻塞仿真 |
| 存储 | SQLite(WAL) + 快照/命令日志 | 单机零运维、崩溃秒级恢复、单文件备份；**替代旧实现 368 处全量 JSON 重写** |
| 数据 | AMF3 发行 + JSON 工作 + schema 单源 | 保容器兼容；工作格式便于工具/校验；schema 生成 C# 类型 |
| 资产 | 离线转码为图集帧序列 | **图集是硬前提**（draw call 差 100 倍）；实测资产无骨骼，帧序列与数据形态一致 |
| 机器人 | 无头客户端核心 | 机器人跑真人同一条 View→Command 路径 ⇒ 本身就是回归测试 |
| 多窗口 | 单进程多窗口（显式关 embed） | 一份资产/图集/显存；输入路由集中；非焦点降帧 |
| 运维 | 游戏内面板 + 程序化命令 API | 单进程无需 HTTP 后台；但自动化必须有控制面 |
| 测试 | 见 §5 与《重写方案》§5 | 无规格项目里测试是规格的载体 |
| 分发 | Godot 自包含导出 | 端用户零安装，符合 C2 与许可边界 |

## §4 被否决方案与否决理由

| 方案 | 否决理由 |
|---|---|
| **多进程（服务端/窗口/机器人各自进程）** | 仿真上限不变；资产与显存按进程重复占用（窗口数反而从 8–12 掉到 4–8）；引入 IPC/守护/跨进程调试成本。**仅在出现"必须拆"的触发条件时切换**（见《重写方案》§7） |
| **Haxe + OpenFL**（务实替代栈） | 保住 AS3 心智、50 万行可直译；但**要求保留 Flash/AS3 语义与 5,425 SWF 运行时**，与"现代工具链 + 图集化 + 编译期边界"目标冲突。**作为成本受限时的替代栈保留**（见 §7） |
| **保留 Flash 运行时（Ruffle/ActiveX）** | 零改动可跑，但 AVM2 API 覆盖不足（Ruffle 官方口径 AVM2 语言 90% / API 82%）且 TCP Socket/AMF3 报文有未修 issue；无长期安全更新。**仅作短期保底** |
| **TypeScript/Web（PixiJS/Phaser）** | 无 `htmlText`/`filters` 等价物；AS3 无法机械翻译 → 446,566 行真实类全部重写，工作量最大 |
| **Unity 6** | 专有编辑器与授权不确定性（Personal 档有营收/融资门槛）；运行时更重；对"长期公开、可自由分发"的项目不友好 |
| **Go / Java / Node 服务端** | 需自研 AMF3 与分帧（生态稀疏：仅 Python Py3AMF 活跃；C# mtanksl 2020 停更；Go 无生产级实现）；Java 还带来 JVM 随包体积问题 |
| **PostgreSQL / MySQL / Redis** | 引入外部服务与安装侵入性，违反 C2；关系型收益在本场景（单机、单写者）不存在 |
| **Spine / DragonBones 骨骼动画** | Spine 运行时需商业授权（违反 C1 精神）；DragonBones 社区实现已停维护；且实测资产**无骨骼数据** |
| **Protobuf/FlatBuffers 作为唯一格式** | 需为 56 段 / 5,135 子段重建 schema 与工具链，收益低于成本；改为"AMF3 发行 + JSON 工作" |

## §5 未验证项（不得当结论引用）

| # | 项 | 解除方式 |
|---|---|---|
| V1 | **AC 供电下的真实帧率上限**（当前测量被电池策略封顶 30 fps） | 接电源重跑 `spikes/godot-multiwindow/bench2.ps1` |
| V2 | **真实资产上传后的显存与帧率**（25,307 位图 tag） | M3 阶段用真实内容跑 B3 基准 |
| V3 | **C#/.NET 确定性**（无并发写、无字典序依赖、浮点） | 两次运行状态哈希比对 |
| V4 | **FlasCC `decodeData` 等价实现**（183 类 / 65,934 行 AVM2 字节码，算法未核实） | 原客户端抓解密后字节 vs 自研实现，单类对照 |
| V5 | **SWF→帧表覆盖率**（嵌套 MC / 锚点 / 矢量 3,998 个 DefineShape / 滤镜） | 全量 5,425 SWF 跑通并统计失败率 |
| V6 | 目标 C# 实现的机器人容量（当前只有遗留 Python 的 700–900 实测） | M4 里程碑复跑同类基准 |

## §6 成本受限时的替代栈（一句话）

若"重写 50 万行客户端 + 6 万行服务端"的成本不可接受：**客户端改用 Haxe 4.3.x + OpenFL（直译 AS3，保 AS3 心智）、服务端保留 Python 3.13+ 标准库并模块化重构、协议保持原 wire 格式**；**"命令唯一入口、事件溯源、逻辑边界"三条规则不变**——它们与语言无关，是两套方案共同的地基。
