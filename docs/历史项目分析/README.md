## 1. 范围与方法

### 1.1 分析对象

`res/` 下 **22 个文件**（19 个压缩包 + 2 个安装器 + 1 张图片 + 1 份攻略 + 1 份 docx），合计 **11,570,587,353 B（11.57 GB / 10.78 GiB）**，覆盖 4 条技术路线、8 个可独立运行的游戏端、4 套修改工具链。

### 1.2 三层证据法

| 层 | 做法 | 产物 |
|---|---|---|
| L1 包级 | 对 22 个原始文件逐个计算 SHA-256，确认身份、去重与完整性 | `C:\Project\hy_analysis\res_sha256.tsv` |
| L2 清单级 | 全部解包（含嵌套包）后对每个解包树做逐文件 SHA-256 清单，建立增/删/改三向账目 | `C:\Project\hy_analysis\deep\hash_*.tsv`、`pair_*.txt` |
| L3 源码级 | 对改动文件做函数/类/路由/动作级 diff；SWF 用 FFDec 反编译到 ActionScript 源码、GameData.dat 解 zlib 流做二进制 diff；Java 用常量池/注解解析；存档与文档全读 | `C:\Project\hy_analysis\deep\dA~dI\` |

> 解包与中间产物保存在仓库外的 `C:\Project\hy_analysis\`（`x\`=第一批 6 包、`x2\`=第二批 7 目录），不纳入仓库。仓库内只保留结论性文档与已解包的 `versions/2.2.1/`。

### 1.3 判定规则

1. **版本号以 `.nya-version.json` 为准**，不以压缩包或目录名为准（`火影世界单机端2.2.1(九月).zip` 实为 **2.2.0**）。
2. **"内容改动"与"行尾重存"必须分开计**：LF→CRLF 重存会造成大量假改动，判定时先去掉 `\r` 再比。
3. **同尺寸不同内容 ≠ 对抗性篡改**：可能是重编译、缓存或压缩差异，须逐项定性。
4. **版本规模只认实测解包数**：包内 `.nya-version.json` 的 `fileCount` 是「该次云更新实际下载替换的文件数」（写入实现 `tools/local_package_update.ps1:391` → `$changes.Count`），不是包内文件总数；另外解包目录里可能混入分析工具生成的 `__pycache__/*.pyc`，须剔除。
4. **包内自述文档只作为线索**，与代码冲突时以代码为准，并记录"文档与现实不符"。

## 5. 结论速览（详细论证见各报告）

1. `res/` 不是"一个游戏的多个版本"，而是**四条独立技术路线 + 一个民间魔改生态**：2012 原版（Java/PHP）、Nya 官方线（纯 Python）、复刻组线（C#/Java 重制）、Nya 魔改四家。
2. **命名陷阱**：[res/火影世界单机端2.2.1(九月).zip](../../res/火影世界单机端2.2.1(九月).zip) 内部实际是 **Nya 2.2.0**（`nya-local-2.2.0-20260810`，versionCode 10）；真正的 2.2.3 在 [res/单机-九月原版/](../../res/单机-九月原版/)。
3. **唯一干净基线**是 2.1.1 v8（内层包，无存档）；其余包几乎都夹带存档、日志与开发痕迹，其中 **wdnm 与嗯哼含明文账密与真实玩家存档**。
4. **民间补丁反向流入官方**：掉落修复补丁（08-11）的 additive/replacement 掉落模型被官方 2.2.3 采用；官方数据编辑器源码（08-16）直接公开发布。
5. **AI 辅助开发是四条线的共同底色**：Nya 线的 `.codex-temp` 构建路径与 `codexbaseline1` 账号、复刻组线的 `codex_gate_*` 门禁表与 `.claude\` 目录、姬水县人的 42 章交接文档与 verify 脚本体系、地图编辑器的 21 轮反馈记录。
6. **安全性普遍薄弱**：原版与复刻组游戏侧明文密码、Nya 魔改多处关闭 GM 鉴权/跳过完整性校验、wdnm 前端开奖可无限刷元宝。
7. **收录价值排序**：2.1.1 v8（干净基线）> 官方 2.2.3 > 2.2.0 > 复刻组 NarutoWorld（第三条路线完整实现）> 姬水县人（工程量最大）> tzl/wdnm/嗯哼（须先清洗隐私）。
8. 全部关键数字的独立复核结论见 [11-数据核验报告.md](11-数据核验报告.md)；与该报告冲突时以其为准。

## 6. 维护约定

新增 `res/` 资源时，按顺序补齐：

1. 计算 SHA-256 并登记到本文件第 2 节与 [../../VERSIONS.md](../../VERSIONS.md)；
2. 解包到仓库外工作目录，生成逐文件哈希清单；
3. 与最接近的既有基线做三向账目（增/删/改），区分行尾重存；
4. 新增/更新对应分析报告，并在 [10-横向对比报告.md](10-横向对比报告.md) 中更新对比矩阵；
5. 在 [11-数据核验报告.md](11-数据核验报告.md) 追加核验记录。

**收录红线**：含他人存档、明文账密、日志个人信息的包，公开收录前必须清洗或明确标注。
